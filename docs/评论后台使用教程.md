# 评论系统使用教程

> 适用：fuwari 博客 + 自建 Twikoo（`https://twikoo.austin666.top`）
>
> 也支持切换成 giscus（GitHub 账号登录才能评论），见 §7。

## 0. 先分清三样东西

| 东西 | 地址 | 说明 |
| --- | --- | --- |
| 博客（静态站） | `https://www.austin666.top` | Astro 构建出来的 `dist/`，纯静态 |
| **评论后台** | `https://www.austin666.top/admin` | 静态页面，跟着博客一起发布，输密码才能用 |
| 评论接口 | `https://twikoo.austin666.top` | 只给程序调用，**浏览器直接打开只会看到一串 JSON，这是正常的** |

所以：**不要再打开 `https://twikoo.austin666.top/admin`**，那个地址不存在（它把任何路径都当接口请求，回你
`{"code":100,"message":"Twikoo 云函数运行正常…"}`）。

真正的后台是博客域名下的 `/admin`。

## 1. 后台怎么用

打开 `https://www.austin666.top/admin`（会自动跳到 `/admin/`）。

### 1.1 登录

第一次打开是登录页，输入管理密码（就是 §4 里说的那个）。登录状态存在**当前标签页**的 sessionStorage 里，
关掉标签页就要重登；顶栏有「退出登录」。

> 密码不写在页面里，也不存 localStorage。密码通过 md5 后作为 accessToken 发给后端校验，
> 和服务端 `ADMIN_PASS` 比对，所以密码本身不会出现在任何请求里。

### 1.2 七个视图

| 视图 | 能看到什么 | 能做什么 |
| --- | --- | --- |
| **仪表盘** | 总评论 / 已通过 / 待审核 / 用户数；评论最多页面、活跃用户 Top5、待办 | 点待办跳到对应筛选 |
| **评论管理** | 全部文章的评论（分页 20 条/页） | 搜索、`全部/已通过/待审核` 筛选、详情、通过、隐藏、置顶、删除、批量操作 |
| **用户管理** | 按 uid 聚合的访客：评论数、地区、最近活跃 | 搜索；筛「有待审评论」 |
| **管理员** | 登记的管理员名单：用户名、名字、「管理员」标签 | 添加 / 移除；「一键填入我自己」 |
| **自动化规则** | 5 条真实规则的状态与命中数 | 只读（改动去审核设置） |
| **GitHub 集成** | giscus 接入状态与步骤 | 只读 |
| **审核设置** | 人工审核开关、频率/长度限制、违禁词与屏蔽词 | 直接写回 Twikoo 后端 |
| **审计日志** | 本次会话你做过的所有操作 | 清空 |

### 1.3 审核流程

后台已开启「人工审核」（`AKISMET_KEY = MANUAL_REVIEW`）：

1. 访客提交评论 → 只有他自己能看到，带一个「审核中」标签，别人看不到
2. 你打开 `/admin` → 仪表盘点「N 条评论等待审核」，或「评论管理」切到 **待审核**
3. 点 **通过** → 立刻对外公开；点 **隐藏** → 打回待审；点 **删除** → 彻底删除

### 1.4 违禁词 / 屏蔽词

`审核设置` 页里两组标签，直接输入回车添加，点 × 删除，最后点「保存全部设置」：

| 配置项 | 现在 | 命中后的行为 |
| --- | --- | --- |
| `FORBIDDEN_WORDS` | 30 个词 | **静默标记为垃圾**（进待审队列，不提示对方，防试探） |
| `BLOCKED_WORDS` | 6 个词 | **直接提交失败**（会提示「包含屏蔽词」，容易被试词） |
| `AKISMET_KEY` | `MANUAL_REVIEW` | 全站人工审核 |
| `LIMIT_PER_MINUTE` | 未设置（默认 10） | 同一 IP 每 10 分钟最多条数 |
| `LIMIT_LENGTH` | 未设置（默认 500） | 单条评论最长字数 |

> 注意：`MANUAL_REVIEW` 的判断排在违禁词前面，两个都开时以审核为准 —— 所有评论都会进待审，
> 违禁词的意义是「审核关掉时它接管」，以及 `BLOCKED_WORDS` 直接挡掉最明显的垃圾，不污染待审队列。

## 2. 部署到服务器（线上）

博客是纯静态，`/admin` 就是多出来的一个 `admin/index.html`，**不需要改 nginx、也不需要重启动 Twikoo**。

```bash
# 本地构建（产物在 dist/）
cd aicode/fuwari
npm run build

# 打包（或直接用现成的 dist.zip）
# 把 dist/ 里的全部内容覆盖到服务器上的网站根目录
```

**服务器上要做的事**：把 `dist/` 的内容覆盖到站点根目录（和 `index.html` 同级），确认新出现：

```
<站点根目录>/admin/index.html
```

然后访问 `https://www.austin666.top/admin` 验证。

- nginx / OpenResty / 宝塔 / 1Panel 的静态站点：直接覆盖目录即可，`/admin` 会自动 301 到 `/admin/`
- 如果你在 nginx 里写了 `location / { try_files $uri $uri/ /index.html; }`，`/admin` 也能正常命中
- 只有一种情况要动配置：如果站点是「严格白名单」只放行固定路径，记得把 `/admin` 加进去

## 5. 安全说明

- `/admin` 是公开可访问的静态页，但**没密码看不到任何东西**，评论数据全部由后端鉴权
- 这页已经加了 `noindex, nofollow`，搜索引擎不会收录
- Twikoo 后台目前**没有限制密码错误次数**，密码请用强口令（建议 12 位以上随机）
- 想再加一层防护，可以在 nginx 给 `/admin` 加 Basic Auth 或只允许你的 IP —— 这是可选的，不影响使用

## 6. 常见问题

**Q：`https://twikoo.austin666.top/admin` 打不开，只有 JSON？**
正常。那是接口地址，后台在博客域名下的 `/admin`。

**Q：`/admin` 报 404？**
说明 `dist/admin/index.html` 没传上去，或者被站点白名单拦了。检查站点根目录里有没有 `admin` 文件夹。

**Q：后台能看到评论，但博客上不显示？**
八成是还在待审（`只看隐藏` 里能找到）。点「显示」。

**Q：评论框右下角的齿轮没了？**
是我按你的要求隐藏的（`src/components/comment/index.astro` 里那条
`#tcomment-wrap .tk-icon + .tk-icon { display: none }`），删掉这行就恢复。

**Q：忘记管理密码？**
密码存在 Twikoo 容器里的数据文件（`/app/data`）中，可以在服务器上删掉 `ADMIN_PASS` 字段重新设置，
或者把数据取出来我帮你处理。

## 7. GitHub 账号评论（giscus 登录 + Twikoo 存储）—— 已启用

**评论必须登录 GitHub 才能发，但评论数据存回你自己的 Twikoo**（不再是 GitHub Discussions）。

分工是这样的：

- **giscus 只负责登录**：它是现成的 GitHub OAuth App，不用部署任何东西。登录成功后会把你的
  GitHub 昵称/头像交给页面，评论框里的昵称/邮箱/网址会自动填好并锁死，别人没法冒名顶替。
- **Twikoo 负责评论本身**：IP 归属地（如「上海」）、浏览器（如「Chrome 141 / Windows 10」）、
  先审后发、违禁词、管理员徽章 —— 全是 Twikoo 自带的，一样不少。
- 结论：**服务端不用再部署 Artalk**，twikoo.austin666.top 一个后端就够了。

### ★ 一次性准备：建一个标题为 giscus-login 的帖子

giscus 只有在 discussion 已存在时才会把登录者身份抛给页面（见它源码 `components/Giscus.tsx`：
`if (!emitMetadata || !data.discussion.id) return`）。所以要先建一个帖子：

> https://github.com/Austinzhao039/fuwari/discussions/new?category=Announcements&title=giscus-login

**标题必须正好是 `giscus-login`**（和 `src/config.ts` 里 `giscus.loginTerm` 一致）。
不建的话，登录弹窗里不会出现「Sign in with GitHub」入口，谁都发不了评论。

配置（`src/config.ts`）：

| 项 | 值 |
| --- | --- |
| provider | `giscus` |
| repo / repoId | `Austinzhao039/fuwari` / `R_kgDOQrqIAw` |
| category | `Announcements`（`DIC_kwDOQrqIA84DJkEC`） |
| mapping | `pathname`（一篇文章 = 一个 Discussion） |
| lang | `zh-CN` |

> 为什么用 Announcements：这个分类只有维护者能新建 Discussion，giscus App 代发，
> 普通用户没法绕过评论区自己去仓库开帖。

### 评论去哪了 / 怎么管

### ★ 为什么必须 `strict=0`（登录帖找不到的真正原因）

giscus 源码 `services/github/getDiscussion.ts`：

```js
const resolvedTerm = strict ? await digestMessage(term) : term;
const searchIn = strict ? 'in:body' : 'in:title';
```

- `strict=1`：把标题哈希掉，去**正文**里搜 —— 那是你给「私密帖」设计的安全模式，
  按标题命名的帖子永远搜不到，表现就是一直报 `Discussion not found`。
- `strict=0`：按**标题原文**搜 —— 这才是我们要的。

所以登录用的 iframe 固定 `mapping=specific` + `term=giscus-login` + `strict=0`。

### 游客没登录时 giscus 报的 viewer 是 `giscus[bot]`

giscus 是拿自己的 App 身份去查帖子的，所以游客没点「Sign in with GitHub」时，
`viewer.login` = `giscus[bot]`。**绝不能把它当用户身份**，否则谁都能以 giscus[bot] 的名义发评论。
代码里已经把这个账号排除掉了。

### 图片上传（≤5MB）：浏览器直传 img520.com

Twikoo 1.6.44 内置的图床**一个都用不了**（都实测过）：

| 图床 | 结论 |
| --- | --- |
| sm.ms / smms.app | 首页 16 秒、API 9 秒；Twikoo 1.6.44 的 smms 通道直接 404 |
| 7bu.top | 收费（空间套餐） |
| imgos.cn | 也是收费的（500M 2元/月、1G 3元/月），免费额度只有 10MB |
| 蜜蜂图床 beeimg.cn | 2026-10-27 起遭 DDoS 封停（10-29 恢复），备用节点同样在防护页 |
| imgkr.com 图壳 | 已挂 |
| img.luoca.net | "不存在的存储驱动"，坏的 |
| img520.com | ✅ 匿名可传、返回 `data.links.url`、`ACAO:*` 放行 CORS |

所以图片**不走 Twikoo**，改成浏览器直传第三方，再把 Markdown 插进评论框：
点图片按钮 → 选图 → 上传 → 评论里自动出现 `![图片](https://img520.com/xxxx.png)`。

好处：**不用注册、不用 token**，页面里没有任何密钥。

配置在 `src/config.ts`：

```ts
media: {
    uploader: "img520",                                  // none = 关闭，只能贴链接
    endpoint: "https://img520.com/api/v1/upload",        // 换成别家同接口时改这里
    maxImageMB: 5,
},
```

换图床只要对方满足三条：匿名（或带 token）可传、返回 `data.links.url`、响应带 `Access-Control-Allow-Origin`。

#### 已知短板

- img520 是个人公益站，**长期稳定性没保证**，重要图片请自己另存一份。
- 图片首次加载偏慢（实测 5–8 秒，他们的 CDN 冷启动），之后走缓存会快。
- 图片直链的状态码是 **404 但内容正确**（浏览器照常显示），用脚本校验时别被 404 误导。
- 视频仍然传不了（Twikoo 的图片按钮只收图片），评论里请贴 B 站/YouTube 链接。

#### 想要更稳？

`deploy/img-host/` 里有一个 200 行的自建图床（兰空 V2 协议，容量只受硬盘限制），
配合 `scripts/set-image-cdn.mjs` 可以把 Twikoo 切回 `lskypro` 模式走自建。
实在不想碰服务器的话，就先用 img520 顶着。

## 8. 评论区里的「管理员」徽章

你（管理员账号）在博客评论区发帖时，名字后面会多一个粉色的 `管理员` 徽章，其他访客没有。

```
Ⓐ Austinzhao039 [管理员] 2 天前
```

### 名字从哪来

就是「管理员」页签里那份名单，存在 Twikoo 后台配置的 `ADMINS` 里。构建时脚本会：

1. 用 `.env` 里的 `TWIKOO_PASS` 登录后台，读出 `ADMINS`
2. 给名单里每个 GitHub 账号生成一条徽章规则
3. 把规则写进 `public/giscus/light.css` / `dark.css`

名单里填的必须是 **GitHub 用户名**（不是昵称、不是显示名），因为 giscus 的评论作者身份由 GitHub 提供，
徽章靠 `https://github.com/<用户名>` 这个链接匹配。

### 为什么改完要重新构建

评论区是 giscus 的 `<iframe>`（`giscus.app` 域名），外部页面改不了它里面的 DOM。
唯一的正规入口是 `data-theme` 指向一个 CSS 文件 —— 也就是说徽章必须在**构建时**写进那个 CSS。
所以：**在后台改完名单 → 重新构建 → 部署，徽章才会变**。后台「管理员」页签里会显示
「生成于 …」，名单和构建结果不一致时会标红提示。

构建 + 上线一条龙：

```bash
npm run build                     # 会自动重新生成 public/giscus/*.css
git add -A && git commit -m "更新管理员名单" && git push
curl "https://purge.jsdelivr.net/gh/Austinzhao039/fuwari@main/public/giscus/light.css"
curl "https://purge.jsdelivr.net/gh/Austinzhao039/fuwari@main/public/giscus/dark.css"
# 然后把 dist/ 覆盖到站点根目录
```

### 为什么 CSS 放在 jsDelivr

giscus 用 `<link crossorigin="anonymous">` 加载主题，**必须带 CORS 头**，而本站 nginx 不发
`Access-Control-Allow-Origin`，直接放自己域名会被浏览器拒掉（表现为评论区没样式）。
jsDelivr 拿的是同一个仓库里的 `public/giscus/*.css`，自带 `ACAO: *`，所以能加载。

如果哪天想彻底摆脱 CDN：在站点 nginx 里加一段，然后改 `src/config.ts` 的 `themeBase`。

```nginx
location ^~ /giscus/ {
    add_header Access-Control-Allow-Origin "*" always;
}
```

```ts
themeBase: "https://www.austin666.top/giscus",
```

### 加载失败会怎样

页面先给 giscus 内置的 `light/dark` 主题，加载成功后才换成带徽章的那份。
CDN 挂了 / 文件 404 时，giscus 会保留内置主题 —— **评论区照常能用，只是没有徽章**，不会变成没样式的白板。

### 想改文案 / 颜色

- 文案：`src/config.ts` 里 `giscus.badgeText`（或构建时给 `GISCUS_BADGE_TEXT=博主`）
- 颜色：`scripts/build-giscus-theme.mjs` 里的 `PALETTE`（浅色/深色各一套）

## 9. GitHub 登录 + IP 属地 + 浏览器信息（Artalk）

### 为什么又要换

| 需求 | giscus | Twikoo | Artalk（自建） |
| --- | --- | --- | --- |
| 必须登录 GitHub 才能评论 | ✅ | ❌ | ✅ |
| 每条评论显示 IP 归属地 | ❌（拿不到访客 IP） | ✅ | ✅ |
| 显示浏览器 / 系统版本 | ❌（拿不到 UA） | ✅ | ✅ |
| 发送前《用户须知》 | ❌（iframe 无法拦截） | ✅（本项目前端实现） | ✅（本项目前端实现） |
| 审核 / 违禁词 | ❌ | ✅ | ✅ |
| 评论存在哪 | GitHub Discussions | 你的服务器 | 你的服务器 |

giscus 是 GitHub 托管在 iframe 里的，访客的 IP 和 User-Agent 我们根本拿不到，也没法在 iframe 里插同意书；
Twikoo 有 IP/UA 但服务端没有账号体系，做不出「必须 GitHub 登录」。**两者都要 → 只能自建 Artalk。**

### 前端已经做完（不用你再写代码）

- `src/components/comment/Artalk.astro`：同意书 → 同意后才加载评论组件 → 挂载 Artalk
- `public/artalk/Artalk.js`、`Artalk.css`：Artalk 前端，**自托管**（不走国外 CDN）
- 主色改成站点粉色；跟随站点深浅色切换（`setDarkMode`）
- 后端没起来时显示「评论服务暂时不可用」，不会白屏

同意书文案在 `src/config.ts` 的 `commentConfig.consent`，改完文案记得改 `version`（访客会重新看到）。

### 后端部署（约 10 分钟，需要你的服务器）

完整步骤见 **`deploy/artalk/README.md`**，包含：docker compose、ip2region 数据库、nginx 反代、
GitHub OAuth App 的三处填写、验证命令、常见问题。

### 部署完怎么切

```bash
COMMENT_PROVIDER=artalk npm run build     # 只改构建参数，不动代码
```

## 9. 左侧栏广告位

位置：**「标签」和「运行时间」之间**。组件在 `src/components/widget/AdSlot.astro`，
配置在 `src/config.ts` 的 `adConfig.sidebar`。

```ts
adConfig: {
    sidebar: {
        enable: false,          // ← 换好素材后改 true
        label: "广告",          // 角标文字（法规要求显著标明「广告」，别改掉）
        mode: "image",          // "image" = 图片广告；"html" = 粘联盟代码
        image: "/ads/sidebar-280x250.png",
        link: "https://example.com",
        alt: "赞助商",
        height: 250,            // 占位高度，防止图片加载后页面跳动
        html: "",               // mode="html" 时用这段
    },
},
```

设计上的几个考虑：

- `enable=false` 时**整个节点不渲染**，不会留空白。
- 图片带 `width/height` + 容器 `min-height`，**不会造成布局跳动（CLS）**。
- 链接自动加 `rel="sponsored nofollow noopener noreferrer"`，符合 SEO 规范。
- 角标用「半透明黑 + 白字 + 背景模糊」，深浅广告图上都看得清。
- 图片尺寸：**宽度 ≤280px**（侧栏 `lg:max-w-[17.5rem]`），推荐 280×250。

> **注意**：侧栏是 sticky 的。广告设太高（比如 600px）会让整列超出屏幕高度，
> 「运行时间」会被挤出视口。250px 以内是安全范围。
